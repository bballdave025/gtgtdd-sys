## Per-job evidence sequence

1. Search Asana and both Sheets first by **employer + exact role + requisition/posting ID**. Distinct requisition IDs may represent distinct applications even with the same title. Do not create duplicates or merge unrelated outcomes.
2. Check the relevant month-specific Job Hunt Drive folder for existing JD PDFs, confirmation records, resumes, and cover letters **before** uploading or generating anything.
3. For each concrete lead, retain the employer's **official live job posting URL** and a **separately labeled dated Drive JD PDF** when available. Identify PDF retrieval date and that a saved JD is **not** submission evidence.
4. When there is evidence of application submission, locate/read the actual employer or application-platform email/receipt, verify **job identity, submission date/time, and exactly what was submitted**, and save a durable receipt artifact in the month folder if missing. Label a derived text record as a **derivative**, not the original email or MIME/PDF export. Preserve the original Gmail message link as primary evidence.
5. Track distinct source roles in all records: **Official JD (job posting)**; **JD PDF (saved snapshot)**; **Submission evidence (original receipt/email)**; optionally **Drive receipt record (derived)**. Do not silently substitute one for another.
6. Confirm status: `CAPTURE / LEAD` (not submitted), `SUBMITTED / WAITING FOR`, `FOLLOW-UP / ACTION NEEDED`, or `CLOSED / NO ACTION` in canonical Asana section. An application confirmation is not an interview; an informational-chat decline is not necessarily a job rejection.
7. Reconcile **Current Leads**, **Active Pipeline**, and **Recent Activity**, preserving older dated events and formatting. Update existing rows in place where identities match. Count each *application* once (not each acknowledgment). Refresh summary counts by recomputing from canonical records; do not increment stale sheet totals.
8. Read back altered Asana records, sheet cells and Drive folder contents. Explicitly report unresolved links, mismatched source rows, unverified salary figures, and partial coverage.

## Correctness boundaries

- Avoid inventing source URLs, salary, location, completion state, or submission dates. Mark `UNKNOWN` rather than guessing.
- Do not automatically apply to every lead or fill every task with artificial deadlines. Respect job-search, family and protected research time.
- If current job data differs from this worked example, **newer verified evidence controls**.
- Keep historical context documents immutable as checkpoint snapshots; record later operational changes in dated addenda or task/source truth.

Governing principles: **one canonical job state, multiple useful views**; **capture the branch, stay on the trunk**; **lean-to, not cathedral**.
